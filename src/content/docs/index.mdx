## What it is

PDTF 2.0 makes each piece of property data independently verifiable. A title register extract, an EPC, a local authority search, a verified identity: each is signed by the organisation that produced it, can be checked by anyone who receives it, and can be revoked when it stops being true.

That removes the need to trust the platform or the inbox the data arrived through. The receiving conveyancer, lender or agent checks the signature, not the sender.

The same property applies when the receiving party is software. As more of the work in a transaction is done by AI assistants acting for professionals, a signed credential is a fact an agent can rely on, where a document pulled from an API is only a claim.

PDTF 2.0 is built on W3C Verifiable Credentials for the data and OpenID Federation for deciding who is allowed to issue what. [The trust model, explained without jargon.](/about/trust-model/)

</section>

<section class="home-section">

## Governance

The framework is designed to sit inside the UK Government's Smart Data model. The Property Data Standards Company acts as the sector-specific implementation entity for property, operating a federation trust anchor that issues trust marks to accredited third-party providers. HM Land Registry is identified as the likely lead regulator.

Two pieces of policy frame the work. MHCLG's [Home Buying and Selling Reform Roadmap](https://www.gov.uk/government/consultations/home-buying-and-selling-reform/outcome/home-buying-and-selling-reform-roadmap) commits to a smart data scheme for property, a voluntary accreditation scheme for data standards, and secure sharing of trusted information between professionals. The [CFIT](https://cfit.org.uk/) Open Property coalition is building the shared trust, interoperability and digital property ID infrastructure the market needs, and mapping existing standards, PDTF among them, to a common conformance framework.

## The entity graph

Instead of one large property data pack, PDTF 2.0 works with ten entities. Five carry data: Transaction, Property, Title, Person and Organisation. Five are thin relationship credentials that embody a party's role: SellerCapacity, Offer, Gift, Representation and TransactionRole. Each is verifiable on its own and composes with the others.

So a title credential from HM Land Registry can be checked without the transaction it was issued for. An EPC travels with the property rather than with one sale. A change of seller can be revoked without invalidating everything else in the pack.

<section class="home-section">

## Open standard, open source

PDTF 2.0 is developed by the Property Data Standards Company and published under an open licence. The specifications, reference implementations and tooling are on [GitHub](https://github.com/property-data-standards-co). The architecture is still proposed, not settled: the [consultation](/consultation/) lists the questions we most want challenged.
